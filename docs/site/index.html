SCENARIO 01

Turn an article into audio

For a blog, newsletter or an audio version of a lesson.

Start with
A local article text file and a delivery brief.
You get
One narration WAV; long scripts also retain individual clips.
Walk through this scenario
  1. Prepare. Download the embedded examples, extract them into your project and review the scenario files below.
  2. Preview. Run these offline checks from the project root.
Preview command
framechord generate speech \
  --provider openai --model gpt-4o-mini-tts --voice alloy \
  --text-file examples/article.txt --brief-file examples/narration.md \
  --format wav --output outputs/article.wav --dry-run --json
Open the scenario files
article.txt
A small garden can begin with a single pot. Choose a bright spot, check the soil before watering, and watch how the plant responds. A few minutes of attention each day can help you learn what it needs.
narration.md
Read clearly, with a calm, warm delivery. Preserve every word of the supplied article.

Generate. When the effective inputs and limits are right, remove --dry-run from the generation or batch command. This can incur provider charges. Use returned artifact paths to locate results.

Review. Listen against the original: check every word, names, numbers and sentence endings. A saved WAV does not prove an accurate reading.

The input must already be local text. Fetching a webpage, extracting the article and adapting its wording are separate tasks for your agent.

Give your agent the task

Scenario agent prompt
Use FrameChord to narrate examples/article.txt exactly. Use the delivery notes in examples/narration.md. Preview OpenAI gpt-4o-mini-tts with alloy, show the output path and limits, then generate only when authorized. Report the final WAV, any chunks and pronunciation concerns.

Produce a podcast episode package

Preview command

  --limits-file examples/limits.yaml \
  --output-dir outputs/podcast-kit --dry-run --json
Open the scenario files
podcast-kit.yaml

  - image.yaml
  - podcast.yaml
  - music.yaml
podcast.yaml
schema_version: 2
id: garden-podcast
media: podcast
brief: podcast.md
locale: en-US
turns:
  - id: host-intro
    text_file: host.txt
    selection: {provider: openai, model: gpt-4o-mini-tts}
    settings: {voice: alloy, format: wav}
  - id: guest-answer
    text_file: guest.txt
    selection: {provider: openai, model: gpt-4o-mini-tts}
    settings: {voice: nova, format: wav}
assembly:
  pause_ms: 250
  turn_gain_db: {host-intro: -1}
  loudness_lufs: -19

media: music

01 / SETUP

Set up once. Finish at your pace.

A guided terminal checklist with arrow-key choices, search and clear readiness. Initialization stays offline.

  1. Install and start

    Install without Rust or administrator access. Public release downloads do not require GitHub sign-in.

    macOS / Linux
    curl -fsSL https://maxiplux.github.io/framechord/install.sh | sh
    Windows PowerShell
    irm https://maxiplux.github.io/framechord/install.ps1 | iex

    Already downloaded? Run ./framechord install (Windows ./framechord.exe install). It installs in your user bin directory, adds user PATH when needed, and keeps project files and skills untouched. Use --no-modify-path to preserve profiles. Open a new terminal, then initialize your project. See custom install options or manual release downloads.

    Check, update, or restore the preceding binary
    framechord update --check
framechord update
framechord update --rollback

    Updates verify GitHub’s SHA-256 digest and executable version before replacement and keep one previous binary for offline rollback. Configuration, provider keys, characters, references, generated media and installed skills are preserved. Skill refresh and project initialization remain explicit. Supported release targets: macOS Apple Silicon, Linux x86-64 and Windows x86-64. Checksums are separate from code signing.

    From the source checkout, install with Cargo. Download native binaries directly from GitHub Releases. CI artifacts remain available for development builds. Binaries include the skills and templates.

    Terminal
    cargo install --path . --locked
framechord init ./my-project

  2. Choose Recommended setup

    Init reads the chosen project’s .env, creates it when absent, and appends missing GEMINI_API_KEY, OPENAI_API_KEY, FISH_API_KEY, OPENROUTER_API_KEY and ELEVENLABS_API_KEY entries with empty values. Existing values, comments and unrelated entries stay intact. Shell credentials take precedence and are never copied into the file. With no destination, this is the folder where you run the command; an explicit project owns its own .env. On save, both .agents/skills/framechord/ and .claude/skills/framechord/ are installed by default. Select fewer agents with --agents codex or --agents claude. Existing modified skills and character models are preserved.

    If this folder contains the downloaded executable named framechord, start with ./framechord init ./my-project. Setup needs its own framechord/ directory. Setup detects name conflicts before the checklist and offers a project folder; existing files stay untouched. When PATH is omitted, --project selects the destination, otherwise the current folder is used. An explicit init PATH takes precedence. The full destination appears before setup and during save review.

    Google is the default: Nano Banana 2.1 handles images and infographics; Gemini 3.8 Flash TTS uses built-in Kore for speech and podcasts; Lyria 3.5 handles music; Gemini 3.8 Flash handles planning. Set GEMINI_API_KEY to make these defaults locally ready. OpenAI is the second welcome option, or use --preset openai for images, speech with coral, and planning. Standalone effects remain optional with ElevenLabs. Providers never change automatically.

    Use arrows and Enter, type to search, and Escape to return. The wizard loops back to this checklist after every section:

    Setup checklist
    Features and models
API keys
Voices
Agent skills
Characters (optional)

Review and finish setup
Save unfinished setup and exit
Discard changes and exit

  3. Reuse your key and review the voice

    An existing GEMINI_API_KEY is read automatically from the shell or this project’s .env. The default Google voice is Kore; the OpenAI alternative uses coral. Keep the built-in voice or change it in Voices. Missing keys can be entered without echo; values are written only when you save. No provider voices are created and setup makes no network calls.

    Review your choices before saving. Finish requires all enabled features to be locally ready. Save unfinished setup and run init again to resume. Existing configuration, character references and credentials are preserved unless explicitly changed.

  4. Check readiness

    Terminal
    framechord --project ./my-project config status --json
framechord --project ./my-project config show --json

    Local readiness does not verify authentication, billing, account voice access or media quality. For an explicit read-only authentication check:

    Optional online check
    framechord --project ./my-project doctor --live --provider google --json
For agents: setup without menus

JSON and noninteractive calls never prompt. Read setup_complete and pending_steps: successful scaffold creation can still leave incomplete setup. Use --preset empty for an empty scaffold, or --defaults-file for an exact custom configuration.

02 / THE COMMAND CONTRACT

One pattern, every medium

Tell the CLI what to create, what to read, which model to use, and where the result belongs.

Command pattern — replace the uppercase placeholders
framechord generate MEDIA \
  --provider PROVIDER --model MODEL \
  --brief-file examples/brief.md \
  --output outputs/result.ext \
  --dry-run --json
Choose the right input
OptionUse it for
--prompt / --brief-fileCreative direction. Use one, not both.
--text / --text-fileExact speech. A prompt is not a narration script.
--specStructured infographic copy, numbers, units and layout.
--jobA reusable YAML request, including podcast turns or a cast.
--outputOne final filename. Use --output-dir for a batch or podcast clips.
--dry-runValidate and inspect effective inputs; no provider calls or run creation.
--json --non-interactiveStructured stdout for agents; progress and diagnostics go to stderr.
Generation examples below are previews. Remove --dry-run to generate, after reviewing inputs and limits. Those calls can incur provider charges. Completed results include artifact paths and a durable run ID. Existing output files require explicit --overwrite.

An image for an article

Create a cover, illustration or standalone visual from a specific creative brief.

Terminal
framechord generate image \
  --provider openai --model gpt-image-2.5-flare \
  --brief-file examples/image.md \
  --size 1536x1024 --image-quality medium --format png \
  --output outputs/garden-cover.png --dry-run --json
Input files · image.md
image.md
# Article cover
Purpose: a calm editorial illustration about urban gardening.
Subject: three terracotta pots with leafy herbs on a sunny balcony.
Composition: wide view with empty space on the left for a separately added title.
Style: soft paper texture, forest green and warm cream. No lettering or logos.

article.txt
A small garden can begin with a single pot. Choose a bright spot, check the soil before watering, and watch how the plant responds. A few minutes of attention each day can help you learn what it needs.
narration.md
Read clearly, with a calm, warm delivery. Preserve every word of the supplied article.
Ask your agent
Agent prompt
Read examples/article.txt aloud with FrameChord using OpenAI gpt-4o-mini-tts and alloy. Preserve every word. Preview the request, save the final WAV to outputs/article.wav, and report chunk artifacts if the text is split.

06 / PODCAST

Give each speaker a turn

Author the conversation explicitly. Each turn has its own script, model and voice; the CLI generates clips and assembles the episode.

Terminal
framechord validate --kind job examples/podcast.yaml --json
framechord generate --job examples/podcast.yaml \
  --output-dir outputs/podcast \
  --limits-file examples/limits.yaml --dry-run --json
Input files · podcast.yaml, host.txt, guest.txt, podcast.md
podcast.yaml
schema_version: 2
id: garden-podcast
media: podcast
brief: podcast.md
locale: en-US
turns:
  - id: host-intro
    text_file: host.txt
    selection: {provider: openai, model: gpt-4o-mini-tts}
    settings: {voice: alloy, format: wav}
  - id: guest-answer
    text_file: guest.txt
    selection: {provider: openai, model: gpt-4o-mini-tts}
    settings: {voice: nova, format: wav}
assembly:
  pause_ms: 250
  turn_gain_db: {host-intro: -1}
  loudness_lufs: -19
host.txt
Welcome to Small Habits. Today we are talking about making room for a small garden. Where should we begin?
guest.txt
Start with one pot and one plant. Choose a bright spot, and check the soil before watering.
podcast.md
A friendly, concise conversation. Clear articulation and natural pauses. Speak only the exact text assigned to each turn.
Ask your agent
Agent prompt
Build a two-speaker podcast with FrameChord using examples/podcast.yaml. Keep the host and guest scripts exact, preserve turn order, and use separate voices. Preview the two speech requests, then save the final WAV and original clips under outputs/podcast.
This example makes two speech requests when executed. pause_ms, per-turn gain and optional EBU R128 loudness normalization apply to the local assembly. Original clips remain available. Converting an article into dialogue is an authoring step before generation.

09 / REUSABLE CHARACTERS

Define identity once. Review every reuse.

Save stable visual and voice profiles separately from scene direction. Characters are optional for ordinary generation.

Terminal
framechord persona add mira
framechord persona show mira --json
framechord templates export authoring

Edit the new character’s persona.md, visual.md, voice.md and character.yaml. Set explicit models and settings before generation. Templates include identity checklists and reference-sheet briefs.

Stable identity

Face geometry, eye spacing, hair silhouette, body proportions, materials and distinguishing accessories. The original provider/model and accepted references stay pinned.

Scene direction

Pose, action, expression, camera and environment belong in the job brief. They must not silently rewrite the character’s canonical identity.

Create candidates, then explicitly accept one
framechord validate --kind character \
  framechord/characters/mira/character.yaml --json

# Paid generation: only run when you want new candidates.
framechord persona bootstrap mira --output-dir candidates --json

# After you select an actual candidate; replace the path below.
framechord persona accept mira --kind image \
  --reference candidates/SELECTED_IMAGE.png
Acceptance is a separate decision. Bootstrap does not promote its results. Copy the actual candidate path from its JSON result. Never accept a rejected scene merely to unblock later jobs. The latest Mira/Kito sheets still failed visual review; matching the original model is necessary here but does not guarantee likeness.

10 / VOICES

Reuse a saved voice, or design a candidate

Speech voice identity is independent of visual identity. Start with an accessible provider voice binding.

Terminal
framechord voices --provider elevenlabs --account \
  --page-size 10 --max-pages 1 --json

# Replace YOUR_VOICE_ID with a voice ID accessible to your account.
framechord generate speech --provider elevenlabs \
  --model eleven_v3 --voice YOUR_VOICE_ID \
  --text-file examples/article.txt --format wav \
  --output outputs/saved-voice.wav --dry-run --json

For repeatable character speech, save the provider/model, voice binding and delivery description in its voice profile, then use --character path/to/character.yaml.

Voice design and creation previews
framechord persona voice-design narrator --model eleven_ttv_v3 \
  --text-file examples/article.txt --run-id narrator-design-1 \
  --dry-run --json

# After generating and selecting an actual design candidate:
framechord persona voice-create narrator \
  --design-run narrator-design-1 --candidate SELECTED_CANDIDATE_ID \
  --name Narrator --bind --dry-run --json

First create narrator and configure an ElevenLabs speech profile with a voice description. Design returns candidate previews. Creating a saved provider voice and binding it are explicit later operations; remove each preview flag only when intended.

Recorded cloning uses persona voice-clone --request clone.yaml. Start from the bundled clone/consent templates and supply actual selected recordings and permission evidence. Fish recording synthesis uses --voice-sample, --sample-transcript and --consent-file. Do not invent consent or substitute a missing voice.

12 / PARALLEL JOBS

Run independent work together

Keep each job in its own manifest. A batch schedules independent jobs concurrently and preserves successes if another job fails.

Terminal
framechord validate --kind batch examples/batch.yaml --json
framechord batch --manifest examples/batch.yaml \
  --limits-file examples/limits.yaml \
  --output-dir outputs/batch --dry-run --json
Input files · batch.yaml, image.yaml, speech.yaml, limits.yaml
batch.yaml
schema_version: 1
jobs:
  - image.yaml
  - speech.yaml
image.yaml
schema_version: 2
id: garden-cover
media: image
selection: {provider: openai, model: gpt-image-2.5-flare}
brief: image.md
settings: {format: png, size: 1536x1024, image_quality: medium}
speech.yaml
schema_version: 2
id: garden-narration
media: speech
selection: {provider: openai, model: gpt-4o-mini-tts}
brief: narration.md
text_file: article.txt
settings: {format: wav, voice: alloy}
locale: en-US
limits.yaml
requests: 4
images: 2
audio_seconds: 120
speech_chars: 5000
revisions: 1
attempts: 1
concurrency: 2
per_provider: 2

This batch contains one image and one narration. The limits file allows two concurrent jobs, bounded volume and one attempt per job. Limits count requests/media, not dollars. Shared host ceilings still apply.

Terminal
# Paid execution after reviewing the batch preview:
framechord batch --manifest examples/batch.yaml \
  --limits-file examples/limits.yaml --output-dir outputs/batch \
  --async --json --non-interactive

# Replace RUN_ID with the returned run ID.
framechord runs status RUN_ID --json
framechord runs wait RUN_ID
framechord usage --json
Identical effective requests can reuse hash-verified local results. --fresh explicitly generates again. --request-id provides submission idempotency. Batch failures return nonzero while keeping completed artifacts.
13 / REVIEW & RECOVERY

A saved file is the start of review

Generation success means a result was saved and checked structurally. It does not prove accurate text, voice quality or character identity.

Terminal
# Replace ARTIFACT_ID with an ID from generation output.
framechord review check --artifact ARTIFACT_ID --json
framechord review report --artifact ARTIFACT_ID \
  --output comparison.md --json
framechord review status --artifact ARTIFACT_ID --json
  • Images: composition, framing, anatomy and identity against selected originals.
  • Infographics: every word, value, unit, source note and the reading order.
  • Speech / podcast: exact script, speaker, pronunciation, missing words and clip joins.
  • Music / effects: duration, lyrics, texture, distortion and clean endings.
Terminal
# Paid revision: preserves the original and makes a child run.
framechord revise --artifact ARTIFACT_ID \
  --instructions-file examples/revision.md --json
Input files · revision.md
revision.md
Preserve the original composition and identity. Increase the outer margins so the entire subject is inside the image.

For changed copy or scripts, use an updated --source-job. A podcast revision can target --turn guest-answer and reuse unchanged verified clips. Record an actual assessment with review record --file review.yaml and honest human/agent provenance.

Recovery — replace RUN_ID and inspect status first
framechord runs status RUN_ID --json
framechord runs reconcile RUN_ID --json
framechord resume RUN_ID --json
Resume can submit queued or safely retryable work and may incur charges; it preserves successful jobs. Reconciliation can retrieve supported Google interactions with saved request IDs. Other uncertain submissions may need provider/account reconciliation. Do not blindly retry: an unknown request may already have incurred charges. --retry-unknown is an explicit paid-risk decision. Local checks and reports make no AI review call; review check --ai is a separate paid operation.
